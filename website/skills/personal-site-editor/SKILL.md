# Personal site editor

The active site is generated by `website/build.mjs` into `material-demo/dist/site/`. Edit source files in `website/`; do not edit generated HTML. Read [site-map.md](references/site-map.md) for file ownership, routes, and the current interaction model. For Notes writing or a new article, also read [notes.md](references/notes.md).

Preserve the owner's factual boundaries. Do not invent work results, images of their work, personal stories, addresses, travel, publications, or roles. An editorial illustration can identify a record but must not be presented as a research figure or project screenshot. Keep team awards identified as team awards. Keep original PDF files unmodified and preview them with the local PDF.js viewer.

Current direction: compact clear typography, generous but purposeful space, a selective Home, separate Work and Notes, About with one canonical experience record set reached through cities and institutions, ordinary scrolling, contact options opening in place, and a restrained persistent music corner. Images should adapt to light and dark backgrounds. These are design decisions to assess against new user feedback, not a fixed template.

When editing, build with `node website/build.mjs`, check with `node website/check.mjs`, and inspect affected routes in the browser at desktop and narrow widths. State which parts were actually verified. Ask the owner only for missing personal facts or a design choice that materially changes the result; make other reversible improvements directly.
